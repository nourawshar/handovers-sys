Works well (checked, behaves as designed):
- Auth: login sets cookies and returns the user; invalid credentials return one generic error; refresh rotates; reused refresh cookie -> 401; logout returns 204 and the refresh cookie is then rejected; deactivated accounts are rejected on the next request.
- RBAC: writes return 403 for TL / MANAGER / CCM across assets, categories and fields, employees, rooms, departments, users, accounts, wizard, generic, return. Accounts: TL and CCM get 403 on list; MANAGER gets masked password and 403 on decrypt. Audit logs are admin-only (403 for TL, CCM, MANAGER). Report export is 403 for TL and CCM. Users list is 403 for MANAGER and TL.
- Room scoping on asset list and detail: TL sees 16 assets (TR1), fateh (TR2) sees 5; out-of-scope asset detail -> 404; assignment detail for TL in other room -> 404 (the list/detail scope for assignments is consistent except F-12).
- Validation: Zod 400s carry field paths and readable messages; over-long strings, bad UUIDs, bad enums, negative numbers, wrong types, unknown keys (strict bodies) all 400. SQL-ish strings (`' OR 1=1 --`) are inert (0 results). Turkish characters (ş, ğ, ç, ı, İ) round-trip and search case-insensitively. Emoji and quotes in notes are stored.
- Phone wizard: minimal body (no SIM/WA) -> 201 (server side of known #3 is ready); dual-active asset 409 with asset code and name; IMEI duplicate -> 409 UNIQUE_VIOLATION; sim≠WA -> 400 with a clear message; phone-category check -> 400; bitrix in use -> 409 with account identifier and assignment code; full loaded phone (2 SIMs, WA, backup fields, bitrix, 2 chargers) stores all items with the body condition on SIM/charger items.
- Return: comparison CRITICAL for missing SIM/Bitrix/adapter, WARNING for changed charger, INFO for chat-count drift; second return -> 409 CONFLICT with status in the message; photos are not duplicated; timeline has RETURNED + DISCREPANCY entries.
- Asset CRUD: create validates everything and returns the full object; DISPOSED condition forces status DISPOSED; manual ASSIGNED status rejected (400); delete with active assignment -> 409; delete with history -> soft-dispose; hard delete when clean.
- Custom fields: select options, date format, boolean type all validated with specific 400 messages; unknown custom keys -> 400 with the key name; duplicate field key in category -> 409.
- Categories: delete when in use -> 409 with asset and child counts and a hint to deactivate; self-parent rejected; ADMIN-only writes.
- Users: duplicate username -> 409; password <10 chars -> 400; TL needs roomId; CCM scope rules enforced; self-demote / self-deactivate -> 409; password reset revokes sessions; role change to MANAGER clears roomId.
- Accounts: duplicate (kind, identifier) -> 409; password never returned in list/detail (mask); decrypt is admin-only and writes an audit row (account.decrypt).
- Photos: magic-byte check rejects a file with a PNG name and non-image content, and an SVG (400). Only JPEG/PNG/WebP accepted.
- Reports: filters validated (days >= 0, scope enum); CSV has BOM and CRLF, Turkish text intact; unknown slug -> 404.
- Assignment list filters: q matches assignment code, asset code/name, IMEI, SIM number, employee name, work identity name; type/status enums validated; pagination meta correct (page 2 of 42 -> 3 rows).
